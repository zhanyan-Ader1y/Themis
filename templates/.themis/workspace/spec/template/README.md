## 关键定义

### Intent与Specify的区分


#### Intent

Intent 回答**为什么和为了谁**。
```plain text
为什么要做？
当前存在什么问题？
谁受到影响？
期望产生什么结果？
本次做到什么程度？
哪些内容明确不做？
哪些约束不可违反？
不同目标发生冲突时优先什么？

```

这些内容即使技术架构完全变化，也应保持稳定。

例如：
```markdown
## Problem

财务人员目前需要手工复制订单数据完成月度对账，
耗时较长且容易遗漏数据。

## Desired Outcome

财务人员能够获得符合当前查询条件的订单数据，
减少人工整理工作。

## Scope

支持当前租户的订单数据导出。

## Non-goals

- 不支持定时导出
- 不支持跨租户汇总
- 不建设通用报表平台

## Constraints

- 不得破坏现有订单查询行为
- 必须继续遵守现有租户隔离规则
```

#### Specify

Specify 回答**系统必须表现为什么**

```plain text
什么角色在什么条件下可以做什么？
系统收到什么输入时必须产生什么输出？
系统必须维持哪些业务不变量？
异常、失败、边界和并发情况下如何表现？
有哪些外部接口或数据契约？
性能、安全、兼容性达到什么可验证标准？
如何判断每项行为通过或失败？
```

例如：
```markdown
### SPEC-EXPORT-001

当具有订单导出权限的用户，
在订单列表应用筛选条件后发起导出时，
系统必须生成仅包含当前租户且符合当前筛选条件的订单数据。

#### Acceptance Criteria

- 导出结果不得包含其他租户的数据。
- 导出结果必须与请求时生效的筛选条件一致。
- 无订单导出权限的用户不得创建导出任务。
```

> EARS 等受约束需求语法将需求组织为“前置条件、触发事件、系统响应”，目的就是降低自然语言中的歧义、模糊、复合要求、实现泄漏和不可测试性


#### 对比

| 维度 | Intent.md | specify.md |
|---|---|---|
| 主要视角 | 用户、业务、利益相关者 | 系统外部行为 |
| 核心问题 | 为什么做、结果是什么 | 系统必须做什么 |
| 抽象层级 | 目标级 | 行为与契约级 |
| 是否可直接测试 | 不一定 | 必须可验证 |
| 是否描述内部架构 | 否 | 否 |
| 是否包含业务范围 | 是 | 引用并细化 |
| 是否包含业务规则 | 只记录关键原则 | 完整定义可执行规则 |
| 是否包含成功标准 | 结果级成功信号 | 具体验收条件 |
| 是否包含 API | 通常不包含 | 对外 API 契约可以包含 |
| 是否包含数据库表 | 不包含 | 通常不包含 |
| 是否包含技术选型 | 只记录用户硬约束 | 不包含方案选择 |
| 主要审批问题 | “这是不是我要解决的问题？” | “系统这样表现是否正确？” |
| 变化频率 | 较低 | 随需求细化而变化 |
| 下游消费者 | 拆分与规格 Agent | 设计、测试、评审 Agent |

## 关键判断

### 判断一：它描述的是价值还是行为

**Intent:**
```markdown
减少财务人员人工整理订单的时间。
```
这是结果和价值。

**Specify:**
```markdown
系统必须允许财务人员导出当前筛选结果。
```
这是系统行为。

### 判断二：用户指定技术方案时放在哪里

例如用户提出：
> 必须使用现有 Kafka，不允许引入新的消息中间件。

建议分层记录：
**Intent.md**
```markdown
## Stakeholder Constraint

必须复用组织现有 Kafka 基础设施，
不得引入新的消息中间件。

Reason:
避免新增基础设施运维成本和审批流程。
```

**design.md**
```markdown
## Messaging Design

- Topic 结构
- 消息 Schema
- Producer/Consumer 责任
- 重试与死信策略
- 幂等机制
```
即：
> Intent 保存约束及其原因，Design 保存如何落实约束。

### 判断三：验收内容放在哪里

Intent 可以有高层成功信号：
```markdown
财务人员不再需要手工复制订单数据。
```

Specify 必须有可执行验收条件：
```markdown
给定财务人员选择“已付款”筛选条件，
发起导出后，
结果只包含当前租户的已付款订单。
```

**因此：**
```markdown
Intent Success Signal
        ↓ 规格化
Specify Acceptance Criteria
        ↓ 转换
Acceptance Test / Check
```
