# themis

## 职责

本 Skill 是唯一公共 `themis` Spec 治理入口。每条外部消息或续接消息都必须先经过本入口，再进入具体节点。

它只负责：

- 接收消息，判断这是新请求还是对既有 Spec 运行的续接；
- 加载 `.themis/spec/` 下的三份定义，按顺序定位当前节点、核对前置闸门、执行判定，并产出或更新对应工件；
- 在当前动作所需支持缺失时安全降级，停在最近已证闸门。

本入口**不拥有任何语义判断**：节点顺序与前置闸门属 `flow.md`，每一步"怎么判过不过"属 `rules.md`，实例应产出哪些文件、哪些小节属 `template.md`。本 Skill 只负责按顺序加载这三份文件并据其执行，不得脱离三份文件自行创造判据、增删节点或改变节点顺序。

## 加载链

```text
flow.md（定位当前节点、前置闸门是否满足）
→ rules.md 中该节点对应的小节（这一步怎么判）
→ template.md（要产出或更新哪些文件、哪些小节）
```

三份文件按此顺序依次加载：先用 `flow.md` 确认当前处于哪个节点、前置闸门是否已满足；再用 `rules.md` 中该节点对应的小节确认这一步的判据与拒绝条件；最后用 `template.md` 确认要产出或更新的文件与小节结构。不得跳过任一份、不得颠倒顺序、不得只加载其中一份就执行判定或产出。

本加载链不经过 `README.md`——`README.md` 是说明性文档，不参与控制。因此运行时必须被读到的内容（当前强制水平、安全降级）完整写在本 SKILL.md 正文中，不依赖读 README 才能获知。

## 稳定入口位置

- `.themis/spec/flow.md`
- `.themis/spec/rules.md`
- `.themis/spec/template.md`

三条路径全部在 `.themis/spec/` 下。

## 安全降级

当前 validator、evaluator、recorder、digest 与 Invocation host 均 unavailable。当前动作所需支持缺失时：

- 停在最近已证闸门（last proven gate）；
- 明确指明哪些保证处于 unavailable 状态；
- 保留续接点，供后续消息或人工继续；
- 不手写机器拥有的状态；
- 不声称任何转移、持久化、失效、恢复或完成已由机器执行。
