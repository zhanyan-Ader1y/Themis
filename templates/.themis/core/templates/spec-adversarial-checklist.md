# Themis 对抗验证攻击场景库

本文档为 Requirement Questioning 的 Step 4 提供可复用攻击场景。它不替代用户判断或确定性 Gate；每个相关场景都必须在 Draft Spec 中以 `cover`、`accept` 或 `defer` 结束。

## 使用方式

- **low**：只执行独立的五项快速检查表。
- **medium**：选择最高优先级的 1–3 个 AC，对六个维度各选择最相关场景。
- **high**：覆盖全部 AC 和全部六个维度；可按策略进行多轮攻击。
- 对于安全、权限或数据完整性中的 critical 发现，不能只以 `defer` 通过声明式门禁。

## 快速检查表（5 项）

1. **空数据或缺失输入**：输入为空、null 或必需关联缺失时，行为是否明确？
2. **失败状态**：操作失败时，用户如何感知，系统如何恢复？
3. **并发冲突**：两个用户或进程同时执行时，最终行为是否定义？
4. **向后兼容**：现有使用者、数据或接口会受到什么影响，如何验证？
5. **回滚路径**：需要撤销时，操作、数据和用户影响是否清晰？

## 维度 1：边界条件

| ID | 场景 | 攻击问题 |
|---|---|---|
| B1 | 空值输入 | 必填字段为空或 null 时系统返回什么？ |
| B2 | 最大、最小与负值 | 超出有效范围、零或负数时如何处理？ |
| B3 | 超长输入 | 超大文本、文件或批次是否触发安全降级？ |
| B4 | 特殊字符 | SQL、XSS、Unicode 控制字符或 emoji 是否改变行为？ |
| B5 | 关联数据缺失 | 被引用资源删除时，系统能否安全失败？ |
| B6 | 时区与国际化 | 时间、货币或格式化在不同 locale 下是否一致？ |

## 维度 2：并发与竞态

| ID | 场景 | 攻击问题 |
|---|---|---|
| C1 | 同时修改 | 两位用户同时修改同一资源，最终状态是什么？ |
| C2 | 重复提交 | 重复点击或重试是否造成重复副作用？ |
| C3 | 超时后成功 | 客户端超时但服务端已完成时，是否可安全重试？ |
| C4 | 部分成功 | 批量操作部分成功、部分失败时如何呈现和恢复？ |
| C5 | 乱序到达 | 事件或消息乱序时，状态机是否仍正确？ |

## 维度 3：状态转换

| ID | 场景 | 攻击问题 |
|---|---|---|
| S1 | 非法状态 | 不允许的当前状态是否被明确拒绝？ |
| S2 | 跳过步骤 | 绕过必需步骤时，后续操作是否被阻止？ |
| S3 | 状态回退 | 是否可回退，什么条件和证据允许回退？ |
| S4 | 并发状态修改 | 多个进程更新同一状态时如何保证一致性？ |
| S5 | 初始状态 | 首次启动或空数据时，初始状态是否定义？ |

## 维度 4：权限与安全

| ID | 场景 | 攻击问题 |
|---|---|---|
| P1 | 未授权访问 | 未登录或低权限主体是否能访问功能？ |
| P2 | 横向越权 | 用户 A 能否访问或操作用户 B 的数据？ |
| P3 | 数据泄露 | 错误、日志或响应是否泄露 token、PII 或内部细节？ |
| P4 | 注入 | SQL、命令、模板或路径注入输入是否被安全处理？ |
| P5 | 跨站攻击 | CSRF、XSS 或会话边界是否被考虑？ |

## 维度 5：依赖失败

| ID | 场景 | 攻击问题 |
|---|---|---|
| D1 | 外部服务不可用 | API、数据库或队列不可用时如何降级？ |
| D2 | 超时 | 超时与明确失败是否使用不同且可解释的重试策略？ |
| D3 | 异常格式 | 非预期状态码或 HTML 错误体是否安全失败？ |
| D4 | 降级策略 | 使用缓存、默认值还是错误；用户是否知道？ |
| D5 | 恢复后状态 | 依赖恢复后是否自动恢复，需要何种人工介入？ |

## 维度 6：数据完整性

| ID | 场景 | 攻击问题 |
|---|---|---|
| I1 | 部分写入 | 中途失败后，已有数据是否保持一致？ |
| I2 | 格式错误 | 不符合 Schema 的数据是否得到可操作错误？ |
| I3 | 编码问题 | UTF-8、UTF-16、GBK 或二进制数据是否被正确处理？ |
| I4 | 迁移中断 | 转换中断时能否安全恢复或回滚？ |
| I5 | 大数据量 | 超出内存限制时是否采用合适的流式或分批处理？ |

## 结果记录

| 处置 | 记录位置 | 含义 |
|---|---|---|
| `cover` | Spec 正文或 AC | 当前交付明确覆盖该场景。 |
| `accept` | `Limitations and Deferred Work` | 当前版本接受已知限制，并记录理由和风险。 |
| `defer` | `Limitations and Deferred Work` | 后续版本或责任方处理，并记录目标。 |

每个有效攻击必须拥有 `ADV-xxx` 标识、关联 AC、攻击维度、场景和处置。未决发现、超过策略允许的延期，或 critical 安全/权限/数据完整性风险会阻止最终批准。
