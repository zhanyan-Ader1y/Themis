# `.themis` 模块规范

本文件是 `.themis` 安装包的模块级约定，约束**修改本模块的人**。跨模块约定见仓库根 `AGENTS.md`。

模块内各包的合同与当前实现状态见对应的 `README.md`：`spec/README.md`（spec 流程控制面）、`README.md`（安装包合同）。

## 控制面写作

`spec/` 控制面四份文件各答一个问题，职责互不渗透（分界表见 `spec/README.md`）。以下约束保证这条分界不被写坏。

### 引用只指向，不复述

在一份文件里引用另一份文件的内容时，只写**去哪找**，不写**那里说了什么**。

同一句话存两份，改一处忘另一处就是漂移——而消除漂移正是控制面存在的理由。

对照两例，差别在括注写的是位置还是内容：

```text
合规：本节点适用 `rules.md` §4（basic/detail 判定，分类核查在本节点完成）
违规：本节点适用 `rules.md` §1（来源与分层事实源，实现依据须以代码为事实源）
```

前者的括注是**位置信息**——这一节管什么、判定在哪个节点发生；后者的括注是**判据内容**——它把 §1 的判据抄了过来。

同样的区分适用于所有方向：`flow.md` 不复述 `rules.md` 的判据与判定方法，`template.md` 不复述任何判定含义，`README.md` 不含流程或判定内容。

**这条特别容易违反**，因为它对抗写作本能：写"见 §8"时会觉得读者需要知道 §8 大概说什么，于是顺手补一句，而那一句往往正好是复述。真实记录是——本模块重构期间这条被违反过四次，三名执行者、三种上下文，错都发生在"补引用"这个动作上。

**自动核验抓不到它。** 行首格式的反向断言（如 `grep -nE '^- \*\*判据\*\*'`）只能拦住结构化的整段搬运，拦不住散文式复述——四次违反全部逃过了断言，靠人工评审逐句读出来。因此评审控制面改动时，必须逐条读引用的括注，判断它写的是位置还是内容。

### 判据必须有判定者

`rules.md` 每节固定四项：适用节点 / 判据 / 拒绝条件 / 判定者。**任何判据没有判定者就不是闸门**——它会退化成没人能合法勾上的框。

两条推论：

- **适用节点必须覆盖判据实际涉及的全部节点。** 否则单读该节会误判适用范围，破坏"每节自足"。
- **判定者必须对每个适用节点都有真实存在、有权做该判定的角色**，且该角色能在判定时刻拿到判定所需的证据。链尾节点没有下游评审者，需要显式兜底。

### 失败去向必须镜像前置闸门的分支

`flow.md` 每个节点固定四件事：前置闸门 / 产出 / 失效波及 / 失败去向。

前置闸门若带条件分支，失败去向必须一并给出每个分支的停靠点。指向一个在该分支下从未产出结论的节点，等于停在一个从未被证明的闸门，与 fail-closed 冲突。

## 与 `core/` 的关系

`core/` 是 simple/full 双路径模型，与已批准契约 `docs/superpowers/specs/2026-08-07-themis-spec-flow-mvp.md` 的单一路径要求冲突，待端到端 replay 验证后整体删除。

在此之前：`spec/` 与 `skills/` 不得引用 `core/` 的任何路径（引用即断链），也不得复制其合同。查阅取经可以，产出必须重新写。
