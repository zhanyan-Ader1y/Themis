# README 产品概览设计

## 目标

将根 README 定位为面向项目访问者的产品首页，优先说明 Themis 解决的问题、核心特性与目标能力。README 不承担跨模块设计、实现合同、计划队列或任务状态的权威职责。

## 读者与表达原则

README 面向第一次了解 Themis 的开发者、团队技术负责人和潜在贡献者。内容使用产品语言说明用户获得的结果，避免要求读者先理解 Rule、Skill、Agent、状态机、工件绑定或知识存储模型。

所有目标能力必须与当前实现状态明确区分。尚未形成可运行产品的能力使用“目标”“计划支持”等表达，不写成已经可用。

## 信息架构

README 按以下顺序组织：

1. 项目定位；
2. 四项核心特性；
3. 四步核心流程；
4. 核心能力；
5. 一句当前状态；
6. 文档入口；
7. 许可证。

## 项目定位

用两段以内说明：

- Themis 是面向团队的 repo-local、规范驱动 AI Coding Harness；
- 它让 AI 辅助变更更容易澄清、评审、验证和沉淀，而不是让 Agent 不受治理地生成代码。

## 四项核心特性

保留以下稳定产品承诺，并优先表达用户收益：

1. **Spec 前追问**：先理解需求为什么提出、期望结果和必要核心链路，再进入规范细化；
2. **更轻松的 Review**：将完整设计提炼为由抽象到具体的评审内容，并按需提供流程或时序 Overview，降低理解成本；
3. **外部经验可沉淀**：失败、恢复、开发经验和已验证实践可以形成待治理的知识候选；
4. **不断进化的项目知识库**：项目知识与项目经验在保留来源和历史的前提下持续更新，并由人类控制正式发布。

README 不在这些条目中解释 `themis-q`、`review.md`、revision、digest、状态路由或知识数据结构。

## 四步核心流程

仅展示用户可理解的价值流程：

```text
理解需求
→ 设计与评审
→ 实现与验证
→ 验收与知识沉淀
```

每一步简要说明结果：

- 理解需求：收敛动机、目标和核心链路；
- 设计与评审：完成可执行设计，并在实现前让人类高效审阅；
- 实现与验证：在批准范围内落地，由独立验证确认结果；
- 验收与知识沉淀：人工接受实际交付，并按需治理可复用知识。

## 核心能力

以目标产品能力列出：

- 需求动机与核心链路收敛；
- Specification 细化与完整技术规划；
- 图形化、渐进式人工 Review；
- 受批准范围约束的实现与独立验证；
- 人工验收与交付摘要；
- 本地优先、渐进读取、受治理的项目知识和项目经验积累。

只描述能力与保障，不展开模块名、检查器、权限矩阵、工件格式或状态枚举。
