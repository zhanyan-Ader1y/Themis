## 现状：本节点当场重测的缺陷面

**本版不沿用第 1 版的任何数字与诊断，全部重测。** 探针以 Write 工具直接落盘，**不经 shell 转义**——第 1 版的两次误测与本次的一次未遂误判都源于 `printf`／`grep` 把探针里的反斜杠吃掉。

**测法**：期望值取自 bash 直跑（变量展开，不经 `printf`），写成断言后交 `themis verify` 复跑，两者不一致即缺陷。

| 模式 | bash | `themis verify` | 判 |
| --- | --- | --- | --- |
| `SPEC` | `19` | `19` | 对 |
| `\<SPEC` | `19` | `19` | 对 |
| `a\+b` | `0` | `0` | 对 |
| `x\?y` | `25` | **`0`** | **静默错值** |
| `S\|P.*节` | `19` | **`0`** | **静默错值** |
| `\(SPEC\)` | `19` | **`0`** | **静默错值** |
| `S\{1\}PEC` | `19` | **`0`** | **静默错值** |
| `SPEC\>` | `19` | **拒绝执行** | **误拒** |

**两类缺陷，第 1 版只记了一类。**

### 类一：静默错值（四例）

**工具照常返回一个数，只是数错了，且不给任何信号。**

**危险性由一次实测直接坐实**：`\(SPEC\).*节` 的 bash 真值恰为 `0`，工具也返回 `0`——**两者一致，无从分辨工具是算对了还是坏了**。**判据只要恰好写成 `→ 0`，静默错值就会通过。**

### 类二：误拒（一例，第 1 版未记）

`grep -c 'SPEC\>'` 被拒，报"命令含本包不解释的 shell 语法 `>`"。**`\>` 是 grep 的词尾锚，不是重定向。** 成因在 `internal/themis/verify.go` 第 `144` 行——`shellMetacharacters` 以子串匹配判 `>`，不区分它是否落在引号内。

**这一例与类一性质相反**：类一是该报不报，类二是不该报却报。**但它在包内、与平台无关，是可直接修的。**

## 一个判别实验，缩小了病因范围

**同一个元字符，写成 BRE（带反斜杠）坏、写成 ERE（不带）好——但花括号两种写法都坏。**

| 写法 | bash | `themis verify` |
| --- | --- | --- |
| BRE `\(SPEC\)` | `19` | **`0`** |
| ERE `(SPEC)` | `19` | `19` |
| BRE `S\|P.*节` | `19` | **`0`** |
| ERE `S\|P.*节`（竖线不带反斜杠） | `19` | `19` |
| BRE `S\{1\}PEC` | `19` | **`0`** |
| ERE `S{1}PEC` | `19` | **`0`** |

**据此可以断定的**：不是元字符本身过不去（ERE 的括号与竖线都过去了），**问题与反斜杠、以及花括号有关**。

**本节点不断定机制。** 第 1 版正是因为断定了一个未经证实的机制而全盘作废；**机制的确证属详细设计，不属 Intake**。
