## 核实到的、影响做法的四处事实

### （1）致坏条件已刻画出来，(b) 因此可行——**这是本节点最要紧的核实**

**规则**：命令的某个参数**同时含反斜杠与 `*` `?` `[` `]` `{` `}` `(` `)` 之一时坏**，否则正常。

**16 个数据点，无一例外**（两轮探针，期望值取自 bash 变量展开直跑）：

| 模式 | 反斜杠 | `*?[]{}()` | bash | 工具 | 规则预测 |
| --- | --- | --- | --- | --- | --- |
| `SPEC` | 无 | 无 | `19` | `19` | 好 ✓ |
| `\<SPEC` | 有 | 无 | `19` | `19` | 好 ✓ |
| `S\|P` | 有 | 无 | `20` | `20` | 好 ✓ |
| `\|` | 有 | 无 | `209` | `209` | 好 ✓ |
| `SPEC*` | 无 | 有 | `19` | `19` | 好 ✓ |
| `节.*SPEC` | 无 | 有 | `5` | `5` | 好 ✓ |
| `\(SPEC\)` | 有 | 有 | `19` | **`0`** | 坏 ✓ |
| `S\{1\}PEC` | 有 | 有 | `19` | **`0`** | 坏 ✓ |
| `\(S\)\|P` | 有 | 有 | `20` | **`0`** | 坏 ✓ |
| `S\|P.*节` | 有 | 有 | `19` | **`0`** | 坏 ✓ |
| `S\|P[A-Z]` | 有 | 有 | `20` | **`0`** | 坏 ✓ |
| `S\|P?` | 有 | 有 | `19` | **`0`** | 坏 ✓ |
| `x\?y` | 有 | 有 | `25` | **`0`** | 坏 ✓ |
| `S\|P)` | 有 | 有 | `19` | **`0`** | 坏 ✓ |
| `SPEC\|节.*的` | 有 | 有 | `47` | **`0`** | 坏 ✓ |
| `SPEC\>` | 有 | 无 | `19` | **拒绝** | 好（另属类二）✓ |

**第二轮是专门的证伪轮**——挑规则预测会坏但"看起来无害"的（`S\|P)`）与预测会好但含 glob 元字符的（`节.*SPEC`），**四条预测全中**。

**本节点明确不主张的**：**这不是穷举证明。** 16 点拟合不等于规则正确，**详细设计须把它做成可跑的测试并扩大取样**，而非直接照抄本表。

### （2）精确规则比保守规则少拒 `27` 条，占反斜杠断言的 `36%`

| 指标 | 值 | 占比 |
| --- | --- | --- |
| 工件中可提取出命令的断言行 | `413` | — |
| 含反斜杠的（保守规则会拒） | `75` | `18.2%` |
| **命中精确规则的（精确规则会拒）** | **`48`** | **`11.6%`** |
| **精确规则得以保留的** | **`27`** | 反斜杠断言的 `36%` |

**这个数同时说明另一件事**：**当前有 `48` 条既有断言，经 `themis verify` 复跑会得到错值**，占全部断言的 `11.6%`。**多数当初是手工实跑核的，未经该工具**——但工具已上线，**这 48 条是它现在就会算错的**。

### （3）类二误拒的成因在包内，与平台无关，可直接修

`verify.go` 第 `144` 行 `shellMetacharacters = []string{">", "&", ";", "$(", "`"}`，**以子串匹配判定，不区分是否落在引号内**。故 grep 的词尾锚 `\>` 被判成重定向。

**`\<` 未被误拒**：`<` 不在该列表里（该行注释写明输入重定向由本包自行解释）。**两者处理不一致本身即是缺陷的一部分。**

### （4）第三类缺陷：表格转义会执行失败**并遗留挂起的子进程**——本节点复现

**第 1 版称"会挂起"，本节点复现并测准了形态**：断言形态写在 Markdown 表格单元格内、管道按表格规则转义为 `\|` 时——

- 工具报 `命令执行失败：… \| …：exit status 3840`；
- **随后进程不退出**，`timeout 25` 触发（退出码 `124`）。

**即：它先给出一个错误，再挂住。** 成因与第 1 版所记一致（`\` 残留使 `wc -l` 从不启动，`grep -r` 转为读标准输入），**本节点未再独立确证该成因**——属详细设计。

## 本节点新暴露、不在 R1 已批准内容里的一处

**R1 批准时只知两类缺陷，本节点确证了第三类**（表格转义 → 执行失败 + 进程挂起）。

**它是否纳入本 step**：本节点判**纳入**，依据是 R1 已批准的收敛主张原文——"`themis verify` 不得再返回静默错值；拒绝须精确到实际会坏的条件"。**挂起比静默错值更明显，但它同样是"工具没能正确执行作者写的命令"**，且与类一、类二同处一段命令构造代码。

**本节点如实标出这是一处自行判定**，交 R2 复核是否越出 R1 批准范围。
