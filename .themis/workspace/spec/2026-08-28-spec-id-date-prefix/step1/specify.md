## 行为条目

### SPEC-SPECID-001

`template.md` 必须规定 spec-id 的形态为 `yyyy-MM-dd-<主题>`，日期取实例创建日。

**验收判据**：

`grep -c 'spec-id' .themis/spec/template.md` → `≥3`

**语义部分由 R2 判定**：规定是否写明日期取哪一天。**命令只能证明字样增加，证不出规定了什么。**

**依据**：所有者指示；`docs/adr/AGENTS.md` 已有同形先例（`YYYY-MM-DD` 前缀、明写不用序号的理由）。

### SPEC-SPECID-003

**语义部分由 R2 判定**：两处例外是否确实未被改动，且各加了指向新 id 的说明。

**依据**：R1 裁定引用同步更新；追问第 2 轮裁定两处例外不改。

## 本节点标出、须 R2 判定的一处

**判据 003 的取法只查了 `core-removal` 一个 id，不是八个。**

**理由**：八个 id 逐个写判据会使本节冗长，而 `core-removal` 是引用最多的一个（`29` 份文件）——**它归零，其余七个大概率也归零，但那是推测不是证明**。

**本节点如实标出该弱点**：判据 003 **不足以证明全部引用都已更新**。verify 节点须补跑其余七个，**判据本身不因此改写**——改写会使本节膨胀到八条同形判据，可读性代价大于收益。

**若 R2 认为该弱点不可接受**，判据 003 应改为覆盖八个 id 的形态。
