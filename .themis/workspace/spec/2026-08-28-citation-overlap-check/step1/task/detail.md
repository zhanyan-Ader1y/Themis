### T-D1 — 极大公共片段检出

**行为目标**：`internal/themis/overlap.go` 能找出两份文本之间所有极大的连续公共片段（长度 ≥ 阈值）。

**做法**：

1. **测试先写**：`TestMaximalExtension`——构造一段两文件共有的长句，断言**报出一处完整长句、而非多处等长窗口**。**先看它红，再实现。**
2. **算法**：对源文本逐行滑窗取 `N` 字（默认 `20`）；窗口命中目标文本后**向右逐字延长直到不再命中**；输出极大片段后，**从极大段尾部继续扫描**，避免同一段被反复报出。
3. **行首噪音**：比对前剥掉行首的 Markdown 标记（`#`、`>`、`*`、`|`、`` ` ``、`-`、空白），否则同为列表项的两行会因标记相同而虚假命中。
4. **按 rune 处理**，不按 byte——控制面是中文，按 byte 切窗会切碎字符。

**对应 `specify.md` 条目**：判据 SPEC-OVERLAP-002。

**依赖的基础任务**：无（basic 段为空）。

### T-D2 — 正当重合过滤，规则随报告输出

**行为目标**：过滤掉正当重合，**并在报告里列出应用了哪些规则、各排除多少处**。

**做法**：

1. **测试先写**：`TestLegitimateOverlap`——断言小节名清单被排除、散文句不被排除；**另断言报告文本里含规则说明与计数**。**先看它红，再实现。**
2. **三条形态规则**（来自实测）：含 ` / `（小节名清单）、含 `、`（节点名并列）、以 `.themis` 或 `SPEC-` 开头或整体被反引号包裹（路径与编号）。
3. **规则输出不可省**——判据 003 要求排除规则可见。**排除规则藏在代码里时，被误排除的违规无人能发现**，那是用新盲区补旧盲区。
4. **规则是经验性的，须在报告中标明这一点**，不得让读者以为它是完备判据。

**对应 `specify.md` 条目**：判据 SPEC-OVERLAP-003。

**依赖的基础任务**：无。

### T-D3 — `overlap` 子命令入口

**行为目标**：`themis overlap` 可运行，比对 `.themis/spec/` 四份文件的 `12` 个有序方向，输出报告；**退出码恒为 `0`**（参数错误或文件读不到除外）。

**做法**：

1. **测试先写**：`TestOverlapCommand`（子命令可调用并产出报告）、`TestOverlapExitCode`（**发现重合时退出码仍为 `0`**）。**先看它们红，再实现。**
2. **入口形态**与既有 `verify` 子命令一致，加在同一 `switch` 中，**不新开包**。
3. **退出码语义与 `verify` 不同，须在 `usage` 里写明**：`verify` 发现不一致返回非零（确定性错误），`overlap` 不返回非零（待人判断的线索）。
4. **不改 `verify` 的任何既有行为**（判据 005 护住）。

**对应 `specify.md` 条目**：判据 SPEC-OVERLAP-001、004。

**依赖的基础任务**：无。

## 判据 005 无任务承担，理由

`SPEC-OVERLAP-005`（"不得使 `verify` 既有行为改变"）**带 `[横切]` 标识，不映射到任何任务**。

它验证的对象是 `verify` 子命令的既有行为——**那不是本 step 的产出**，本 step 只要求别弄坏它。判定依据见 `rules.md` §12 的横切边界。
