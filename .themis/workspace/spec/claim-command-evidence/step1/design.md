# design.md — claim-command-evidence / step1

> 本文件是详细设计节点的实例工件（为 R2 投影需要 Overview 而提前产出，与前三个实例同型）。结构决策归属见 `rules.md` §6。以上各处只指向位置，本文件不复述其文字。

## 架构与边界

本 step 改动落在**一份文件**：`.themis/spec/template.md`，新增一节「断言形态」。

**不改** `rules.md`（判定者的归属见「结构决策」第 3 条，落在既有条款内）、**不改** `flow.md`、**不写任何代码**。

## 结构决策

### 1. 形态：`` `命令` → `输出` → `断言值` ``，中段可省

以既有自发写法 `` `命令` → `值` `` 为基础，**在中间插入一段"原样输出"**：

```text
两段式（输出即断言值时）：  `wc -l < x.md` → `116`
三段式（据输出写下别的值时）：`ls -1 x/` → `a.md b.md c.md` → `3 个文件`
```

**为什么中段可省**：绝大多数断言的输出就是断言值本身（计数、行数、存在性），强制三段会让常见情形凭空多写一遍。**中段只在"据输出推出另一个值"时才需要**——而那正是 `.gitignore` 那次错误的形态（输出 11 行、结论写 10）。

**CLI 的比对规则由此确定**（本 step 只定形态，规则写明供 step2 消费）：两段式比对命令输出与断言值是否**相等**；三段式先比对命令输出与中段是否相等，**再由人判断中段到断言值的推导**——CLI 判不了后者，它是语义推导。

**这一处如实标出局限**：三段式下 CLI 只能拦住"输出记错"，拦不住"输出对但推导错"。`.gitignore` 那次若按三段式写，CLI 会发现输出是 11 行、而中段若也写 11 则通过，**结论那个 10 仍不被拦**。**要拦住它需要 CLI 理解"从 11 行推出 10"是否成立——那是语义判断，不在本设计范围。**

### 2. 落点：`template.md` 新增一节，不改小节划分表

形态是**写法约定**，不是某份工件的小节。它适用于所有工件的所有数字，因此不属于小节划分表的任何一行。

**新增独立一节「断言形态」**，与该文件既有的「实例目录树」「文件小节」并列。

### 3. 判定者：验证角色，在验证时判——CLI 可用后接管

`specify.md` 标出本 step 最尖锐的问题：形态的最终判定者是 step2 才存在的 CLI，而本 step 验收时它不存在。

**本设计取「验证角色在验证时判」**，理由有三：

- **它在本 step 验收时真实存在**——`rules.md` §7 已规定验证角色须逐条对照判据给出断言，读形态是否合规只是把"逐条对照"扩大一个维度，不增加新角色。
- **它拿得到证据**——形态是否合规可从工件文本直接读出，不需要跑任何东西。
- **CLI 可用后不需要改条款**——CLI 接管的是"重跑比对"，而"形态是否合规"仍需有人判（CLI 遇到不合形态的断言只能报错，报错之后仍是人来修）。**两者不冲突，是先后关系。**

**不取「推迟到 step2」**：那违反「判据必须有判定者」，且形态在 step2 落地前完全无人把关——而 step2 可能很久之后才做。

### 4. 不做形态的机器校验

本 step 只规定形态、由人判合规性。**"形态本身是否被机器校验"属 step2**——CLI 读取时自然会遇到不合形态的断言。

**不在本 step 加一条"形态须由 CLI 校验"的条款**：那会声称一个尚不存在的机器强制，违反 `docs/design/themis-design.md` 约束 7。

## 取舍

1. **中段可省 vs 强制三段。** 取可省——强制三段让常见情形凭空多写一遍，而 `scope.md` 第（3）条已标出：形态过重会被规避，**规避与没有约束等效**。代价是两种形态并存，CLI 需分辨（按箭头数量分辨，机械可判）。

2. **以既有写法为基础 vs 另设计一套。** 取前者，依据是 `scope.md` 命令 S4：该写法在三实例中 0→7→12 处递增、已被验证可写可读。代价是它不是从机器可读性出发设计的，**中段是补进去的而非原生的**。

3. **判定者取验证角色 vs 推迟到 CLI。** 取前者，理由见「结构决策」第 3 条。**代价如实标出**：验证角色判形态合规性，仍是人判人写的东西——**本需求要治的正是"人判自己写的东西不可靠"**。此处是无奈之选：CLI 不存在时没有更好的判定者。**这一点必须让 R2 评审者知道，不得掩饰。**

4. **不拦"输出对但推导错"。** 取不拦，因为它需要语义判断。代价是 `.gitignore` 那次错误的**完整形态仍不被拦**——CLI 只能拦住其中"输出记错"那一半。
