## 投影

### 这一步要做什么

让"评审通过"这件事，在事后能被看出来它到底是不是评审者本人说的。

现在的情况是：每次评审或验收，Agent 会写两样东西——一个结论（通过/不通过），和一段你的原话。**这两样都由 Agent 自己写。** 没有任何规则要求它写的结论必须真的来自你的答复。

于是如果 Agent 从一句不构成批准的话里"补"出一个批准，产出的记录和真批准**长得一模一样**。事后谁都看不出来。

### 需要你裁定

**无。** 追问已闭合四问，本节点无新增待裁定项。

### 改变了原定方向的发现

**这件事在本项目已经发生五次，而且每次都是我自己按住的——不是被任何规则拦住的。**

- 两次在删除旧 core 目录那个需求里：一次是我把自己的推论写成"这是评审者第 2 条要求的"，引用格式完全合规，只是你的原话里根本没那句；一次是你答了个单字母 `a`，那只回了一个选项、不含验收结论，但 `a` 恰好也能读成"同意"。
- 三次在刚做完的清理需求里：抽象设计评审、详细方案评审、人工验收各一次，形态都是你给了结论没给并列的裁定项，或者反过来。

五次都没造成实际越权。**但这正是问题所在——它依赖我每次都主动停下来追问，而不是依赖任何机制。**

### 其余要点

**这个需求做不到"阻止"，只能做到"可被发现"。** 本项目没有 Themis 的命令行工具（只有另一个模块 Themico 的），控制面自己也写明机器强制不可用、闸门靠 Agent 遵守。没有机器就没有拦截点，写一条"禁止推断补足"只是又一条靠自觉的规则——**而自觉正是已经失效五次的那个东西**。你已认可这个强度。

**因此只做三层做法里的第三层。** 前两层（机器落盘原话、机器比对引用真伪）都需要那个不存在的命令行工具。

**这个选择有代价，你已知情**：第三层只覆盖五次里的四次。"把推论写成评审者要求"那一类不被覆盖——它的引用格式合规，只有逐字比对原话才能发现，而逐字比对属于第二层。

**判定者取"下一次引用这个结论的角色"**，这是你定的。它与控制面里链尾工件的兜底机制同型，**弱点也同型：如果没有下一次引用，这个判定就永远不会发生**。设计阶段必须处理这一点，不能回避。

### step 分解（本节点一并确认）

**一个大步骤**，同时改两处：

- 控制面（规则）——规定评审结论的合法取值、来源要求，以及谁在什么时候判。
- 呈现规范（怎么向你提问）——规定授权和附带裁定必须分开问，一次只问一个待决项。

**为什么不拆成两个**：这两处治的是同一个问题的两端。规则管"结论怎么写才算数"，提问方式管"怎么问才不会逼出推断"。拆开会让一端先落地、另一端悬空，而**单独任何一端都不足以改变失效形态**——只补规则不改提问，仍会系统性产出只答一半的回复；只改提问不补规则，答全了也仍然没有来源约束。

### 我知道但还没解决的

- **五次实发里有一次不被本需求覆盖**（伪造引用那一类），需要第二层，而第二层需要那个不存在的命令行工具。
- **判定者的固有弱点**：无人引用则判定不发生。设计阶段须给出处理方式。
- **本需求自身也受这个问题影响**——本次评审、以及后面的每次评审和验收，都是它的又一次实测机会。若期间再次发生，我会如实记录，不因"正在修它"而回避。
