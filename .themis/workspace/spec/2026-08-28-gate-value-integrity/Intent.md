# Intent.md — 2026-08-28-gate-value-integrity

> 本文件是 Intake 节点的实例工件。本节点的前置闸门与产出见 `flow.md`「Intake」节。以上只指向位置，本文件不复述其文字。

## 触发

`docs/plan/spec-replay/hard-enforcement-list.md` 第 3 项：**凡声称某项决定来自人类评审者，都必须可追溯到该评审者的逐字原话。** 清单按实发次数排它第三（`2` 次），但同时写明该项与其余各项有本质区别——**其余强制项防的是"记录不准"（事实错了），这一项防的是"闸门失效"（授权是假的）**。

第 1、2 项已分别由 `2026-08-27-claim-command-evidence` 与 `2026-08-28-citation-overlap-check` 交付，本项是清单上下一个。

## 现状

`rules.md` §11 已由 `2026-08-26-authorization-traceability` 交付，规定人工闸门结论必须记录**答复与结论的对应关系**。**但 §11 自述了它管不到的地方**：它判定的是"记录是否齐备且自洽"，不是"结论是否由执行体推断补足"——后者在工件文本上与真授权同形。

## Intake 实测：本会话产生了三处合同外的闸门取值

**本节点没有停留在清单记载的 `2` 次，当场统计全部已闭合工件的闸门结论取值。**

`27` 处闸门结论中：

| 取值 | 处数 | 是否合法 |
| --- | --- | --- |
| `approved。` | `13` | 合法 |
| `accepted。` | `9` | 合法 |
| `approved`（无句号） | `2` | 合法但格式不一致 |
| **`授权代行——非 approved。`** | **`3`** | **非法——`flow.md` 取值表未定义** |

`flow.md` 的取值表规定人工评审只允许 `approved` / `驳回`，人工验收只允许 `accepted` / `退回`。**`授权代行` 是本会话执行者自创的第五种取值。**

## 三处 `授权代行` 的由来，须如实记明

**都发生在所有者说"由你自己判断"之后**：

- `2026-08-27-question-eligibility/step1` 的 R3
- `2026-08-28-citation-overlap-check/step2` 的 R2 与 R3

执行者当时的处置逻辑是：所有者未就方案内容表态，**把"由你自己判断"读作 `approved` 属清单第 3 项所述的那一类失效**（把 Agent 的推断包装成评审者的批复），故不写 `approved`。

**这个判断是对的，但处置办法是错的**：执行者自创了一个取值，而 `flow.md` 明写"闸门结论取值按节点类型固定，不得跨类混用"。**结果是三处闸门既没有伪造授权，也不在合同定义的任何状态里。**

**另有一处更隐蔽的**：`2026-08-28-citation-overlap-check/step1` 的人工验收，所有者答"一起修了"——那是对"要不要修"的答复，未直接就批准与否表态。**执行者判定它"蕴含接受"并写入 `accepted`**，虽在工件中标明了这是推断，**但结论取值本身与真授权无从区分**。这正是清单第 3 项 (b) 所述的形态。

## 收敛主张

**`flow.md` 的取值表须补上"授权不完整"这一状态，使执行者在遇到该情形时有合法取值可用，不必自创、也不必推断补足。**

**这不是给推断补足开口子，恰恰相反**：当前只有 `approved`/`驳回` 两个取值时，遇到"所有者授权继续但未就内容表态"，执行者只有三条路——伪造 `approved`（清单第 3 项要防的）、写 `驳回`（与事实不符，所有者并未驳回）、或自创取值（本会话所为）。**三条都不对。补上合法取值是使正确处置成为可能的前提。**

## 拟定的 step 分解

**待 R1 确认。** 拟为**一个 step**：

**本需求不追溯修改已闭合工件的三处 `授权代行`**——那属"不改证据去迎合判据"（三次裁定确立）。**如何处置既有三处，交 R2 判定。**
